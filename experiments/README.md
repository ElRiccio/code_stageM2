# experiments

One module per numerical question raised by the reviewer, built on
`ns_core`. An experiment module exposes a function that runs the
computation and returns its raw results (a dict or small dataclass of
tensors/scalars); it does not plot or save anything. `plotting.py` holds
the shared, experiment-agnostic plotting helpers that turn those results
into figures.

- `plotting.py` — generic plot helpers (spectrum plots, error-decay plots,
  figure saving), each taking plain arrays and labels rather than an
  experiment's own result object.
- `scripts/` — reproducible drivers: call an experiment function, plot its
  results, save the thesis figures. Run as `python -m experiments.scripts.<name>`.
- `notebooks/` — exploratory notebooks, for iterating on an experiment or a
  figure before it becomes a script. Not meant to be reproducible drivers.

## Running on CPU or CUDA

Every driver in `scripts/` accepts `--device {auto,cpu,cuda}` and
`--dtype {float32,float64}` (`experiments/cli.py`; `svd_device.py` instead
takes `--device {both,cpu,cuda}`, since comparing devices is its whole
point). `--device auto` (the default) picks CUDA if available, else CPU.
Output filenames/CSV columns are tagged with the device used, so a CPU and
a CUDA run of the same driver don't overwrite each other:

```
python -m experiments.scripts.svd_timing --device cuda --dtype float32
```

## Modules

- `convergence_order.py` / `scripts/convergence_order.py` — empirical
  validation of the order-(D+1) convergence rate, scalar and matrix.
- `rank_deficiency.py` / `scripts/rank_deficiency.py` — iterations-to-
  tolerance of the matrix sign map itself under rank deficiency and
  conditioning sweeps.
- `map_catalogue.py` — shared, experiment-agnostic catalogue of the six
  maps under test in the SVD-comparison suite below (five CPWL profiles
  from `ns_core.cpwl`, excluding the leaky rectifier whose rectangular sign
  form is the identity, plus the matrix sign map `msgn`): each map's
  decomposition-free evaluator and its exact SVD-based reference. Also
  `unit_norm_gaussian`, the plain-Gaussian-matrix convention this suite's
  parameter knots are chosen against.
- `trials.py` — generic repeated-trial helper (`run_trials`,
  `run_trials_multi`): seeded repetition over independent random draws,
  mean/std aggregation, seed logging. Used by every experiment module that
  draws random matrices, per the "repeat and report variability"
  convention (decision 8, extended by decision 18 below).
- `tables.py` — generic CSV writer (`save_csv`), the tabular counterpart to
  `plotting.py`'s `save_figure`.
- **SVD-comparison suite** (reviewer: "there should be a direct comparison
  with the SVD-based implementation: accuracy, computation time, dependence
  on matrix size, possibly GPU vs. CPU"), one module per axis, all built on
  `map_catalogue.py`:
  - `svd_accuracy.py` / `scripts/svd_accuracy.py` — accuracy vs. SVD.
  - `svd_timing.py` / `scripts/svd_timing.py` — computation time vs. SVD.
  - `svd_scaling.py` / `scripts/svd_scaling.py` — scaling with matrix size.
  - `svd_rank_sigma.py` / `scripts/svd_rank_sigma.py` — rank / sigma_min
    dependency at fixed matrix size (accuracy/timing per map, distinct
    from `rank_deficiency.py`'s iterations-to-tolerance question about the
    sign map alone).
  - `svd_degree.py` / `scripts/svd_degree.py` — dependence on degree D.
  - `svd_device.py` / `scripts/svd_device.py` — CPU vs. GPU; degrades to a
    CPU-only table with no comparison plot when no CUDA device is present.

Outputs land in `figures/` (PNG) and `results/` (CSV), both git-ignored
scratch directories regenerated by re-running the scripts (decision 6: no
persistence layer, nothing here is meant to be committed as data).
